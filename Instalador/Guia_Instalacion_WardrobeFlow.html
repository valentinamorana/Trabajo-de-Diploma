WardrobeFlow · Guía de instalación

Cómo instalar WardrobeFlow

Esta guía le explica cómo instalar, actualizar y desinstalar WardrobeFlow en una computadora con Windows, qué hacer si el instalador no encuentra SQL Server y cómo resolver los errores de conexión al iniciar la aplicación. Puede leerla sin conexión a Internet e imprimirla.

Si el equipo todavía no tiene un motor de base de datos, consulte también la guía «Cómo instalar SQL Server para WardrobeFlow».

1. Requisitos

RequisitoDetalle

Permisos de WindowsUna cuenta con permisos de administrador del equipo. Al iniciar el instalador, Windows pide confirmación (Control de cuentas de usuario).

Se requiere SQL Server 2012 o posterior: el instalador muestra la versión de cada instancia para que usted elija.
Permisos en SQL ServerSi usa una instancia existente, la cuenta de Windows que instala debe ser administradora de esa instancia (sysadmin) o, al menos, poder crear bases de datos (dbcreator). Si la base ya existe, debe ser su db_owner. El instalador lo verifica antes de copiar archivos. Con LocalDB no hace falta: su usuario de Windows es el dueño de la instancia.
Espacio en discoAl menos 1 GB libre. El instalador comprueba por sí solo que haya espacio para sus archivos.

2. Instalación paso a paso

Estos pasos corresponden al caso más común: un equipo con SQL Server instalado y su servicio en ejecución. Si el instalador no encuentra SQL Server, vea la sección 3.

  1. Haga doble clic en el instalador (Instalador_WardrobeFlow_….exe). Si Windows SmartScreen muestra un aviso, elija Más información y luego Ejecutar de todas formas (el instalador tiene una firma propia, no de una autoridad comercial). Después, acepte el pedido de permisos de administrador con Sí.
  2. Antes de mostrar el asistente, el instalador verifica que esté instalado .NET Framework 4.7.2 o posterior.
  3. En la página «Seleccione la Carpeta de Destino», confirme la carpeta propuesta (de forma predeterminada, Archivos de programa\WardrobeFlow) y haga clic en Siguiente. En una actualización esta página no aparece: se usa la carpeta de la instalación anterior.
  4. En la página de tareas adicionales, marque Crear un acceso directo en el escritorio si lo desea (viene desmarcada) y haga clic en Siguiente.
  5. En la página «Base de datos: Se encontró SQL Server en este equipo», elija la instancia donde se creará la base WardrobeFlowDB. La lista muestra:
    • cada instancia detectada, con su versión (por ejemplo, .\SQLEXPRESS (SQL Server 2022));
    • SQL LocalDB: (localdb)\MSSQLLocalDB si ya está instalado, o Instalar SQL Server Express LocalDB si no lo está;
    • Otra instancia o servidor (ingresar manualmente), para escribir el nombre de un servidor que no aparece.
    Si es una reinstalación, ya aparece marcada la instancia que se usó la vez anterior (ahí están los datos). Haga clic en Siguiente: el instalador comprueba que el servicio de esa instancia esté en ejecución (si está detenido, intenta iniciarlo) y que su cuenta tenga permisos.
  6. En la página «Listo para Instalar», revise el resumen y haga clic en Instalar.
  7. Espere a que termine. El instalador copia la aplicación, guarda el servidor elegido en la configuración, hace un backup de la base si ya existía, crea o actualiza la base WardrobeFlowDB con sus tablas y datos iniciales, da acceso a los usuarios del equipo y verifica el resultado. El paso en curso se muestra debajo de la barra de progreso.
  8. En la página final, deje marcada la opción Abrir WardrobeFlow y haga clic en Finalizar. Si desea ver las cuentas de prueba, marque también Ver las credenciales iniciales (solo demo).

3. Si el instalador no encuentra SQL Server, no hay motor o el servicio está detenido

3.1. No se encuentra ninguna instancia

Si el instalador no detecta ninguna instancia de SQL Server en el equipo, en lugar de la lista de instancias muestra la página «Base de datos: No se encontró SQL Server en este equipo», con tres opciones:

OpciónCuándo elegirla
Instalar SQL Server Express LocalDB (recomendado, incluido en este instalador; se instala al confirmar)
o, si LocalDB ya está en el equipo, Usar SQL LocalDB, ya detectado en este equipo		La opción predeterminada. Úsela si no tiene SQL Server o si solo va a usar la aplicación una persona.
Ya tengo SQL Server instalado (con otro nombre, o en otro servidor): ingresar manualmenteSi SQL Server está instalado pero no fue detectado, o está en otro equipo de la red. Escriba el servidor y la instancia (por ejemplo .\SQLEXPRESS o SERVIDOR\INSTANCIA). El instalador prueba la conexión (puede tardar hasta 30 segundos) y los permisos antes de seguir; si la conexión falla, le pregunta si desea continuar de todos modos.
No tengo ningún motor de SQL Server instalado: cancelar la instalaciónSi prefiere instalar SQL Server Express completo antes. El instalador se cierra sin instalar nada y le ofrece abrir el tutorial para instalar SQL Server.

Desde esa misma página también puede abrir, sin salir del asistente, el tutorial (Ver tutorial para instalar SQL Server, funciona sin Internet) y la página oficial de descarga de Microsoft (Abrir página de descarga).

3.2. El equipo no tiene ningún motor de base de datos (LocalDB)

  1. En la página «No se encontró SQL Server en este equipo», deje marcada la primera opción, Instalar SQL Server Express LocalDB, y haga clic en Siguiente.
  2. Lea el aviso de que la base de LocalDB es solo de su usuario de Windows y ciérrelo con Aceptar.
  3. En «Listo para Instalar», haga clic en Instalar. Recién en ese momento se instala SQL Server 2022 Express LocalDB, desde el propio instalador y sin descargar nada (aparece una barra de progreso de Windows Installer, sin preguntas). Si cancela antes, no queda nada instalado.
  4. La instalación continúa sobre (localdb)\MSSQLLocalDB, como en la sección 2.
LocalDB es de cada usuario de Windows

La base se crea en el perfil del usuario de Windows que inició el instalador, y solo ese usuario la ve. Si varias cuentas de Windows van a usar WardrobeFlow en el mismo equipo, instale SQL Server 2022 Express (vea el tutorial) y elija esa instancia.

Si la instalación de LocalDB falla, el instalador no instala nada de WardrobeFlow, informa el código de error y la ubicación del registro (Documentos\WardrobeFlow_LocalDB_install.log) y le ofrece abrir el tutorial para instalar SQL Server de otra forma.

LocalDB también aparece en la lista cuando el equipo ya tiene otras instancias: es la salida si su cuenta no tiene permisos sobre el SQL Server existente.

3.3. El servicio de SQL Server está detenido

No necesita hacer nada al principio: al hacer clic en Siguiente en la página de la base de datos, el instalador comprueba el servicio de Windows de la instancia elegida y, si está detenido, lo inicia y espera hasta 30 segundos a que quede en ejecución.

Si no lo logra (el servicio no existe o no se pudo iniciar, por ejemplo por falta de permisos), muestra este mensaje:

El servicio de Windows para esa instancia (MSSQL$SQLEXPRESS) no está disponible (no existe, o está detenido y no se pudo iniciar automáticamente: ¿faltan permisos de administrador?). ¿Desea continuar de todos modos? (se va a reintentar más adelante)
  • No: vuelve a la página para elegir otra instancia. Puede iniciar el servicio a mano (vea «Cómo iniciar el servicio de SQL Server») y volver a hacer clic en Siguiente.
  • Sí: el instalador continúa y vuelve a intentar iniciar el servicio antes de crear la base. Si vuelve a fallar, en una instalación nueva deshace todo lo copiado (rollback automático) y le indica qué hacer.

Esta comprobación se hace para las instancias detectadas en el equipo. Para un servidor ingresado manualmente (posiblemente remoto) no hay un servicio local que iniciar: el instalador solo prueba la conexión.

4. Instalación desatendida

Para instalar sin intervención (por ejemplo, en varios puestos), abra una consola como administrador en la carpeta del instalador y ejecute:

Instalador_WardrobeFlow_….exe /VERYSILENT /SUPPRESSMSGBOXES /SERVIDOR=.\SQLEXPRESS
ParámetroEfecto
/SERVIDOR=servidor\instanciaParámetro propio de WardrobeFlow. Indica la instancia de SQL Server donde se crea la base (por ejemplo .\SQLEXPRESS01, SERVIDOR\INSTANCIA o (localdb)\MSSQLLocalDB). Cuando se usa, el asistente no muestra las páginas de base de datos ni hace sus verificaciones previas (también en una instalación con ventanas). Si el valor coincide con una instancia detectada en el equipo escrita como .\NOMBRE (o . para la instancia predeterminada), igual se comprueba e inicia su servicio antes de crear la base.
/VERYSILENTNo muestra ninguna ventana del asistente. /SILENT muestra solo la barra de progreso.
/SUPPRESSMSGBOXESResponde cada mensaje con su respuesta predeterminada, para que ningún aviso detenga la instalación.
/DIR="carpeta"Instala en otra carpeta en lugar de la predeterminada.
/TASKS="desktopicon"Crea también el acceso directo en el escritorio (sin este parámetro no se crea).
/LOG="archivo"Guarda un registro detallado de todo el proceso del asistente.
/NORESTARTEvita que el equipo se reinicie al terminar.
Qué tiene en cuenta en modo desatendido

Sin /SERVIDOR, se usa la instancia que estaría preseleccionada: la usada la vez anterior (en una reinstalación), o si no la primera instancia detectada; si el equipo no tiene ninguna, LocalDB si ya está instalado.

No se instala LocalDB en modo desatendido: la instancia indicada (o detectada) debe existir. En un equipo sin ningún motor, instale antes SQL Server o LocalDB.

Al terminar no se abre la aplicación ni las credenciales. Si la instalación falla, el instalador termina con un código de salida distinto de 0 y deja el registro en la carpeta Documentos de la cuenta que lo ejecutó.

Para desinstalar sin intervención, ejecute unins000.exe /VERYSILENT /SUPPRESSMSGBOXES desde la carpeta de instalación. En ese modo no se borra la base de datos (la respuesta predeterminada a esa pregunta es No).

5. Primer inicio de sesión

  1. Abra WardrobeFlow desde el menú Inicio (WardrobeFlow) o desde el acceso directo del escritorio.
  2. Al iniciar, la aplicación comprueba la conexión con la base de datos. Si no puede conectarse, muestra el cuadro «Error de conexión» con la causa y qué hacer (vea la sección 8.1).
  3. En el primer arranque de una instalación nueva, la aplicación crea el administrador de respaldo admin2 y diez claves de emergencia de un solo uso, y muestra dos avisos con la ubicación de cada archivo (en Documentos\WardrobeFlow\CredencialesGeneradas del usuario que abrió la aplicación). Guarde ambos archivos en un lugar seguro: las claves permiten desbloquear una cuenta de Administrador bloqueada.
  4. Inicie sesión con una de las cuentas iniciales. Los usuarios y contraseñas de prueba, uno por rol, están en Credenciales_Iniciales.txt: menú Inicio → WardrobeFlow → Credenciales iniciales (solo demo), o el archivo del mismo nombre en la carpeta de instalación. Ese archivo también indica qué usuario conviene usar para cada proceso y qué mirar en cada pantalla.
  5. En el primer ingreso de cada usuario se abre la guía de inicio de su rol. Para una demostración, puede iniciar la aplicación con el parámetro /singuia (por ejemplo, GUI.exe /singuia) para que no aparezca.
Cambie las contraseñas de prueba

Las cuentas de prueba tienen contraseñas fijas, pensadas para la demostración, y se crean solo en una instalación nueva. En un uso real, el Administrador debe entrar en Administrar → Usuarios → Administración de Usuarios, pestaña Cuentas, y usar Resetear Contraseña en cada cuenta (en el siguiente ingreso, el sistema obliga a definir una contraseña nueva). Después, borre o restrinja Credenciales_Iniciales.txt.

6. Actualización de una versión anterior

  1. Cierre WardrobeFlow en todos los puestos.
  2. Ejecute el instalador de la versión nueva. No aparece la página de la carpeta de destino (se usa la anterior) y la instancia usada la vez anterior aparece seleccionada.
  3. Antes de modificar la base, el instalador genera un backup completo, WardrobeFlowDB_pre_<versión>_<fecha y hora>.bak, en la carpeta de backups de la instancia de SQL Server (<versión> es la versión que se está instalando). Lo hace siempre que la base ya existe, también al reinstalar la misma versión. Si el backup falla, el instalador se detiene sin modificar la base.
  4. El script actualiza la estructura sin borrar datos ni volver a crear las cuentas de prueba. Al terminar, el instalador verifica que la base tenga al menos un Administrador activo, planes de suscripción y prendas.

Si la actualización falla, no se desinstala nada: se conservan la instalación y la configuración del servidor, y la base puede haber quedado actualizada a medias. El mensaje indica la ruta del backup para restaurarlo, y el registro queda en Documentos\WardrobeFlow_actualizacion_fallida.log. Una vez corregida la causa, vuelva a ejecutar el instalador: continúa la actualización.

7. Desinstalación

  1. Cierre WardrobeFlow.
  2. Abra Configuración → Aplicaciones (o «Agregar o quitar programas»), busque WardrobeFlow y elija Desinstalar.
  3. El desinstalador pregunta: «¿Desea borrar también la base de datos WardrobeFlowDB?». El botón predeterminado es No, para no perder datos por error. Elija Sí solo si quiere eliminar toda la información; esta acción no se puede deshacer.
Se eliminaNo se elimina
  • La aplicación, sus documentos y los accesos directos.
  • Los registros de la carpeta de instalación.
  • La base WardrobeFlowDB, solo si eligió Sí. En ese caso también se quita el acceso del grupo Usuarios, si ninguna otra base lo usa.
  • La base de datos, si eligió No.
  • Los backups de la carpeta Backups (si contiene archivos, la carpeta queda).
  • Los backups previos a las actualizaciones (en la carpeta de backups de SQL Server).
  • Los registros guardados en Documentos y los archivos de Documentos\WardrobeFlow\CredencialesGeneradas.
  • SQL Server y SQL Server LocalDB.

Si no se pudo borrar la base, la aplicación se desinstala igual, se avisa con el código de error y el detalle queda en Documentos\WardrobeFlow_desinstalacion.log. Con LocalDB solo se borra la base del usuario de Windows que ejecuta el desinstalador: si la base era de otro usuario, debe borrarla esa persona desde su sesión.

8. Solución de problemas

8.1. Mensajes de «Error de conexión» al iniciar WardrobeFlow

Antes de mostrar la ventana de inicio de sesión, WardrobeFlow comprueba que puede conectarse a la base. Si no puede, muestra el cuadro «Error de conexión» en el idioma de Windows (español, inglés, ruso o portugués; si es otro, en español) y se cierra. El mensaje indica la causa, el servidor configurado y, al final, dónde está la cadena de conexión:

La cadena de conexión 'WardrobeFlowDB' está en: …\GUI.exe.config (o reinstale WardrobeFlow y elija otra instancia de SQL Server).

Busque en la tabla el comienzo del mensaje que vio:

MensajeCausaQué hacer
La base de datos 'WardrobeFlowDB' no existe en el servidor '…'.
 El servidor responde, pero no tiene la base (error de SQL Server 4060). Por ejemplo, la base se borró al desinstalar o la aplicación apunta a otra instancia. Instale (o reinstale) WardrobeFlow para crear la base. Si la base está en otra instancia, en la instalación elija esa instancia. Si tiene un backup, restáurelo después desde Administrar → Sistema → Backup y Restauración.
El servidor '…' rechazó el inicio de sesión: su usuario de Windows no tiene permiso sobre la base 'WardrobeFlowDB'.
 Su cuenta de Windows no tiene acceso a la base en ese SQL Server (errores 18456 o 18452). Suele pasar si el instalador no pudo dar acceso al grupo Usuarios o si el servidor es de otra persona. Pida acceso al administrador del servidor de SQL Server: debe dar a su usuario de Windows (o al grupo Usuarios del equipo) acceso a la base WardrobeFlowDB. Reinstalar WardrobeFlow con una cuenta sysadmin de la instancia vuelve a dar ese acceso al grupo Usuarios.
El servidor '…' no responde: no se encuentra en la red o el servicio de SQL Server está detenido.
 El servidor no existe, no se encuentra en la red, no responde a tiempo o su servicio está detenido (errores -2, -1, 2, 53, 258 o 26). Inicie el servicio de SQL Server (vea «Cómo iniciar el servicio de SQL Server») y vuelva a abrir WardrobeFlow. Verifique también que el nombre del servidor del mensaje sea correcto; si es un servidor de otro equipo, que el equipo esté encendido y accesible en la red.
La instancia LocalDB '(localdb)\MSSQLLocalDB' no responde.
 El mismo caso anterior, cuando el servidor configurado es SQL Server LocalDB. LocalDB se inicia sola al conectarse; vuelva a abrir WardrobeFlow. Si el error se repite, abra una consola (Windows + R, cmd) con su usuario de Windows y ejecute sqllocaldb start MSSQLLocalDB (con sqllocaldb info MSSQLLocalDB puede ver su estado). Si el comando no existe, LocalDB no está instalado: reinstale WardrobeFlow y elija instalar LocalDB.
No se pudo conectar a la base de datos en el servidor '…'. Verifique que SQL Server esté en ejecución. (Error N: detalle)
 Cualquier otra causa. El mensaje muestra el número de error de SQL Server y el detalle técnico. Anote el número y el detalle. Compruebe que el servicio esté en ejecución y que el servidor sea el correcto. Si el número aparece como «-», la falla no vino de SQL Server: por ejemplo, falta la cadena de conexión WardrobeFlowDB en GUI.exe.config o está mal escrita; reinstale WardrobeFlow.

8.2. Dónde está la cadena de conexión y cómo cambiar el servidor

La cadena de conexión está en el archivo GUI.exe.config, junto al ejecutable GUI.exe, en la carpeta de instalación de WardrobeFlow (el mensaje de error muestra la ruta completa). El instalador escribe ahí el servidor que usted eligió, en la entrada WardrobeFlowDB:

<add name="WardrobeFlowDB"
     connectionString="Data Source=.\SQLEXPRESS;Initial Catalog=WardrobeFlowDB;Integrated Security=True;TrustServerCertificate=True;Connect Timeout=30" … />
  • La forma recomendada de cambiar el servidor es reinstalar WardrobeFlow y elegir otra instancia: así también se crea o actualiza la base y se da acceso a los usuarios del equipo.
  • Si solo necesita corregir el nombre del servidor (la base ya existe en él), un administrador puede editar el valor de Data Source con el Bloc de notas abierto como administrador (la carpeta de instalación está protegida). No cambie el resto de la cadena.

8.3. Cómo iniciar el servicio de SQL Server

  1. Presione Windows + R, escriba services.msc y haga clic en Aceptar.
  2. Busque el servicio SQL Server (SQLEXPRESS) o el de su instancia (SQL Server (NOMBRE); la instancia predeterminada es SQL Server (MSSQLSERVER)).
  3. Haga clic derecho sobre él y elija Iniciar. Espere a que el estado cambie a «En ejecución».
  4. Para que no vuelva a pasar, en Propiedades elija el tipo de inicio Automático y haga clic en Aceptar.

Necesita permisos de administrador. SQL Server LocalDB no aparece en «Servicios»: se inicia sola (vea la tabla de la sección 8.1). Más detalles en el tutorial de SQL Server.
