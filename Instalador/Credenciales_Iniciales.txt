WardrobeFlow — Credenciales iniciales (usuarios semilla) — SOLO PARA LA DEMO
==============================================================================

ATENCIÓN: este archivo es SOLO PARA LA DEMOSTRACIÓN ACADÉMICA. Las cuentas y
contraseñas de abajo son FIJAS a propósito, para la presentación y defensa del
trabajo, y este archivo es público (lo puede leer cualquier usuario del
equipo). En una implementación real hay que cambiar todas estas contraseñas
en el primer uso: el Administrador entra en Administrar > Usuarios >
Administración de Usuarios, pestaña Cuentas, y usa «Resetear Contraseña» en
cada cuenta (en el siguiente ingreso, el sistema obliga a definir una
contraseña nueva). Después hay que borrar o restringir este archivo.

Estas cuentas se crean automáticamente SOLO en una instalación NUEVA (ver
BD/00_Instalacion_Completa.sql). Al actualizar una base existente no se crea
ni se recrea ninguna cuenta: si en producción se renombró o se dio de baja un
usuario demo, una actualización no lo vuelve a crear.

Centro de decisiones comerciales: guía para la demo (PN03)
----------------------------------------------------------
Ingresar con gcomercial (o admin) → Promociones → Centro de decisiones
comerciales → Analizar (período por defecto: los últimos 90 días). Los datos
son relativos al día de la instalación; los importes y % de abajo son
aproximados (pueden variar un poco según el día).
  1. Analizar ........... MRR ~ $ 730.000 (sube ~32 %), % de bajas ~17 % contra
                          ~33 % del período anterior (favorable), 18 clientes
                          en riesgo, ingreso en riesgo por plan (Estándar,
                          Básico y Premium), stock por categoría, prendas más y
                          menos pedidas y la tendencia de 6 meses con su
                          proyección de 3.
  1b. Cohortes .......... 6 cohortes comparables con distinta retención. La peor
                          es la de hace unos 5 meses (13 clientes: retiene ~69 %
                          al mes 3 contra ~85 % del promedio) y la explica el
                          plan Básico. "Actuar sobre la peor cohorte" lleva a la
                          recomendación de bajas del Básico.
  2. Recomendaciones .... "Bajas altas en el plan Básico" (33 % de bajas, 10
                          clientes en riesgo): la opción ganadora es una
                          promoción de retención del 30 % durante 60 días →
                          "Simular esta opción" (el Simulador dice Conviene, ROI
                          ~85 %); Aceptar registra la sugerencia, que sigue el
                          circuito Administración → Contabilidad. También:
                          extender "PROMO Vigente Estandar -10%" (también se
                          puede simular), dar de baja "PROMO ConSolicitudBaja
                          Premium $3000", ofrecer el Estándar a Bruno
                          UsaTodoElCupo (tiene las 5 prendas de su plan Básico),
                          escasez (lista de espera) y, solo con la patente de
                          stock (admin, ginventario), prendas sin rotación y
                          mantenimiento excesivo. La campaña de renovación está
                          pospuesta: se ve con "Mostrar ocultas".
  3. Historial .......... 4 decisiones: la Ejecutada de bajas del Básico (estimado
                          $ 12.000, real y medido $ 225.360), la campaña de
                          renovación en medición (4 de 5 contactados ya

                          Descartada con su motivo. "Registrar resultado real"

Guía de primer uso
------------------
En el primer ingreso de cada usuario se abre "Bienvenido a WardrobeFlow" (5
pasos para su rol) y vuelve a aparecer en cada ingreso hasta marcar "No volver
a mostrar al iniciar sesión"; se reabre desde Sesión → Ver guía de inicio.
Para que no aparezca durante la defensa, ejecute la aplicación con el
parámetro /singuia (por ejemplo: GUI.exe /singuia).

Después de actualizar desde 1.5.0 (paso obligatorio)
-----------------------------------------------------
Después de actualizar desde 1.5.0, ejecute Backup → Restablecer datos de demo
(admin → Administrar → Sistema → Backup y Restauración → "Restablecer datos de
demo..."). La actualización migra la base sin tocar los datos: una base 1.5.0
conserva su demo anterior, sin las metas, las decisiones sembradas ni la
historia que usan el Centro de decisiones, las cohortes y el Informe ejecutivo
(se ven pestañas vacías o incompletas). El instalador no la recarga solo
porque borraría los datos cargados.

Restablecer los datos de demo (antes de la defensa)
---------------------------------------------------
Restablecer como máximo 2 días antes de la defensa: las fechas de la demo son
relativas al día en que se cargan (la reserva de la lista de espera dura 48 h,
"por vencer" es a 5 días, el pedido atrasado tiene 35 días...).
  - Desde la app: admin → Administrar → Sistema → Backup y Restauración →
    "Restablecer datos de demo...". Pide confirmación dos veces (escribir RESTABLECER),
    hace un backup sin cifrar en la carpeta de backups
    (WardrobeFlow_PrevioDemo_...bak), borra los datos de negocio (también las
    decisiones comerciales del Centro de decisiones), recarga la
    demo, inicializa los dígitos verificadores, lo registra en la bitácora y
    reinicia la aplicación. Usuarios, permisos, planes, idiomas y la bitácora
    del sistema se conservan.
  - Por SQL: ejecutar BD/Reset_Datos_Demo.sql en SSMS y abrir la aplicación.

Requisitos previos a la instalación
------------------------------------
- No hace falta tener SQL Server instalado: si el equipo no tiene ninguna
  instancia, el instalador ofrece instalar SQL Server Express LocalDB (viene
  incluido) y crea la base ahí. Una base en LocalDB es privada del usuario de
  Windows que instala: otro usuario de Windows del equipo no la ve. Para
  compartirla entre varios usuarios, usar SQL Server Express (o superior).
- Si ya hay instancias de SQL Server (Express, LocalDB u otra), el
  instalador las detecta; si hay más de una permite elegir, y también permite
  ingresar el servidor a mano.
- La cuenta de Windows que instala tiene que ser administradora de la
  instancia elegida (sysadmin) o, al menos, poder crear bases (dbcreator);
  el instalador lo verifica antes de copiar archivos.
- .NET Framework 4.7.2 o superior.
- Paso a paso para instalar SQL Server: menú Inicio > WardrobeFlow > "Cómo
  instalar SQL Server" (Docs\Tutorial_SQL_Server.html en la carpeta de la app).

El instalador crea la base de datos WardrobeFlowDB, todas sus tablas y los
datos de prueba de forma automática durante la instalación. Si el equipo ya
tiene una versión anterior, hace un backup de la base y la actualiza (sin
borrar datos ni crear usuarios demo).

Acceso de otros usuarios de Windows: el instalador le da al grupo local
"Usuarios" el rol db_owner SOLO sobre la base WardrobeFlowDB (no sobre toda la
instancia). Hace falta para que la app pueda restaurar backups aunque la use
otra cuenta de Windows. Quién puede hacer backups o restaurarlos lo decide la
app (solo el Administrador). Riesgo aceptado: alguien con acceso a Windows
podría modificar la base por fuera de la app; esos cambios los detectan los
dígitos verificadores (DVH/DVV) al iniciar.
